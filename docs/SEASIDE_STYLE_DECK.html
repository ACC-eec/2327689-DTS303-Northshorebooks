02 · Inspiration
The Idea

Fable's soul, dressed for the coast.

We keep every structural choice that makes Fable read as an editorial bookshop — wide serif headlines, generous whitespace, pill-shaped search, 2:3 covers — and re-tune only the palette, the accents, and the hero motifs.

  • i.Editorial, not e-commerce. Covers breathe. No crowded grids, no neon badges.
  • ii.Deep sea over forest. Navy is our anchor; it replaces Fable's forest-green hero.
  • iii.Warm sand, not cold cream. Our canvas is softer, more driftwood than paper.
  • iv.Horizon not hand-scribble. Accents are gentle waves and sun forms, not marker strokes.
  • v.Italic serif for personality. Fraunces italic does the job of Fable's green scribble.

10 · Guardrails
Do & Don't

Keep the coast quiet.

Do

Lean editorial.

  • ✓
    Use navy as the weight-carrier. Hero, primary action, logo mark. One dark anchor per screen.
  • ✓
    Let sand do the talking for surfaces. Default page background is --sand-50, not white.
  • ✓
    Reserve coral for single beats. One sale badge, one active step — not a secondary colour family.
  • ✓
    Italicise one word per headline. Fraunces italic is our "scribble."
  • ✓
    Keep book covers simple. Gradient + serif title is our placeholder pattern until real cover art arrives.
Don't

Don't tourist it up.

  • ×
    No bright turquoise / aqua. This is northern coast, not Caribbean pool. Stay in navy family.
  • ×
    No animated twinkling stars. We removed those. A single sun / wave motif is plenty.
  • ×
    No yellow titles on navy. Book titles are always ink or near-white, never saffron.
  • ×
    No seahorse logomark. A simple n in a navy disc does more with less.
  • ×
    No more than two fonts. Fraunces + Inter. That's the whole kit.

11 · Implementation
Hand-off

How to ship this.

Three small edits swap the current mahogany for seaside without touching component structure. Drop these tokens into static/assets/css/ui.css · the rest cascades.

/* static/assets/css/ui.css — replace :root token block */
:root {
  --color-forest-900: #0B3B5C;   /* was #280801 mahogany */
  --color-forest-800: #124B70;   /* was #A85710 */
  --color-forest-700: #2E6B8F;   /* was #6B3A0A */
  --color-cream-50:   #F7EEDD;   /* warmer sand, was already cream-ish */
  --color-ink-900:    #14283A;   /* ink with blue-tint, was #1a1a1a */
  --color-white:      #FFFFFF;   /* was #E8E6E3 — restore pure white */
  --color-border-200: #E6DECC;   /* sand-tinted border */
  --color-muted-600:  #5C6F82;   /* blue-grey muted */

  /* new accent tokens */
  --color-sky-100:    #DCEBF3;
  --color-foam:       #C5E2D3;
  --color-coral:      #E08663;
  --color-sand-200:   #E4D2AE;
}

/* .nav — remove the grey fill */
.nav { background-color: var(--color-white); }

/* .welcome-header — was mahogany + stars */
.welcome-header { background: var(--color-forest-900) !important; }
.star, .star-1, .star-2, .star-3, .star-4, .star-5, .star-6 { display: none; }

12 · Requirements
Coursework

How each page meets the brief.

A direct map from the ten practical requirements to the pages that satisfy them. Same wording lives at the bottom of every page in the live app, so the marker can verify in either place.

HomeReqs 1, 9, 10

The catalogue is open to anyone, no login required. The featured carousel pulls books from the Django ORM and every title is auto-escaped before render. The same catalogue is served as paginated JSON at /api/books/.

Book listReqs 1, 6, 10

Lists every book with title, author, price, and cover. Search and filter parameters route through Django's ORM, never raw SQL, so injection attempts are rejected. Books are paginated, with the same data available as JSON.

Book detailReqs 1, 7, 9

A dedicated page per book showing every field. The Add to basket form carries a CSRF token and is rejected without it. All fields are auto-escaped, so a script tag in a title renders as plain text.

RegisterReqs 3, 7, 8

Creates a new user. Passwords are stored with PBKDF2 and a per-user salt, never plain text. The form carries a CSRF token. Length and common-password validators run server side before the user is created.

LoginReqs 3, 7, 8

Authenticates against the hashed password store. After 5 failed attempts in 5 minutes the username is locked out. The session ID is rotated on success so an old session cookie cannot be reused.

BasketReqs 4, 7, 8

Logged-in users add, change, and remove items before submit. Every form ships a CSRF token. On submit the server recalculates the total from the database, so client-side tampering with prices is ignored.

Order historyReqs 4, 8

Lists every order this user has submitted, read-only. The query filters by request.user, so a customer never sees another customer's orders.

Order detailReqs 4, 8

Read-only line items and total for one submitted order. An ownership check at the view layer 404s any attempt to view someone else's order by guessing an ID in the URL.

Django adminReq 5

Staff add, update, and remove books and view all customer orders through Django's built-in admin at /admin/, with permissions enforced by IsAdminUser.

REST APIReqs 2, 10

DRF endpoint at /api/books/. GET list and detail are public. POST, PUT, PATCH, DELETE are admin-only. JSON responses with built-in pagination and search filtering.
