# API Reference

The Northshore Books prototype exposes a REST API for the catalogue, plus a JWT-based authentication surface for non-browser clients. The rule that runs through it is the one Roy Fielding made standard: every resource carries a stable URL; the verb decides what happens to it; the response is JSON. Reads are public; writes need a staff account.

A quicker route, for anyone who would rather click than read: open `/api/docs/` in a browser. That is the Swagger UI, generated by `drf-spectacular` from the same code paths described below, and it lets a reviewer try requests without leaving the tab.

## 2. Authentication

Two authentication modes are wired up, and a caller can use whichever fits:

- **Session cookies** — used by the website itself. A logged-in customer visiting `/api/books/` from the browser carries their session cookie, and the API treats them accordingly. CSRF protection applies on this path because the cookie path is exactly the case CSRF was designed for.
- **JWT bearer tokens** — used by non-browser clients. Stateless, cookie-free, CSRF-irrelevant.

### 2.1 Obtaining a JWT

```http
POST /api/auth/token/
Content-Type: application/json

{"username": "admin", "password": "your-password"}
```

```json
{
  "access":  "eyJ0eXAiOiJKV1Qi...",
  "refresh": "eyJ0eXAiOiJKV1Qi..."
}
```

- The **access token** lasts thirty minutes.
- The **refresh token** lasts one day and rotates on each use.
- The endpoint is throttled at `5/min` for anonymous callers — the lockout that protects `/accounts/login/` would otherwise be cosmetic, since an attacker could brute-force credentials through this door instead.

### 2.2 Using the access token

```http
GET /api/books/1/
Authorization: Bearer eyJ0eXAiOiJKV1Qi...
```

### 2.3 Refreshing

```http
POST /api/auth/token/refresh/
Content-Type: application/json

{"refresh": "eyJ0eXAiOiJKV1Qi..."}
```

```json
{"access": "eyJ0eXAiOiJKV1Qi..."}
```

### 2.4 Verifying

```http
POST /api/auth/token/verify/
Content-Type: application/json

{"token": "eyJ0eXAiOiJKV1Qi..."}
```

A `200` with no body means the token is valid. A `401` means it is not.

## 3. Books — `/api/books/`

The catalogue resource. Reads are public; writes require `is_staff = True`.

### 3.1 Verbs

| Verb | Path | Purpose | Auth |
|------|------|---------|------|
| `GET` | `/api/books/` | List the catalogue (paginated). | Public. |
| `GET` | `/api/books/<id>/` | Retrieve a single book. | Public. |
| `POST` | `/api/books/` | Create a book. | Admin only. |
| `PUT` | `/api/books/<id>/` | Replace a book. | Admin only. |
| `PATCH` | `/api/books/<id>/` | Update a book in place. | Admin only. |
| `DELETE` | `/api/books/<id>/` | Delete a book. | Admin only. |

### 3.2 Book payload

```json
{
  "id": 1,
  "title": "The Great Gatsby",
  "author": "F. Scott Fitzgerald",
  "isbn": "9780743273565",
  "price": "14.99",
  "description": "A novel of the Jazz Age...",
  "cover_image": "/media/covers/gatsby.jpg",
  "cover_image_url": ""
}
```

- `cover_image` is read-only on the API. Covers are uploaded via the admin or supplied by URL through `cover_image_url`.
- `price` is a string in the JSON to avoid floating-point rounding loss; it is stored as `DecimalField(max_digits=8, decimal_places=2)` server-side.
- `id` is read-only; it is assigned by the database on create.

### 3.3 Filtering

| Parameter | Behaviour |
|-----------|-----------|
| `?author=<name>` | Case-insensitive contains-match on author. |
| `?min_price=<number>` | Lower bound (inclusive). Non-numeric input is silently ignored. |
| `?max_price=<number>` | Upper bound (inclusive). Same. |
| `?search=<query>` | Search across title and author. Truncated to 200 characters. |
| `?ordering=<field>` | Order by `title`, `author`, `price`, or `created_at`. Prefix with `-` to reverse. Anything outside the allowlist falls back to the default. |

The allowlist on `ordering` is deliberate: it stops a curious caller probing arbitrary database columns by name.

### 3.4 Pagination

Page-number pagination is enabled with a page size of ten. The list response carries the standard DRF envelope:

```json
{
  "count": 42,
  "next":     "http://.../api/books/?page=2",
  "previous": null,
  "results":  [ /* ten Book payloads */ ]
}
```

### 3.5 Permissions in detail

The view set checks the action and chooses the permission class accordingly. `list` and `retrieve` are open (`AllowAny`); every other action goes through `IsAdminUser`. A non-admin caller attempting `POST /api/books/` is answered with `403 Forbidden`, and the failure is recorded to `storage/logs/security.log` with `event_type: "admin_access_denied"`.

## 4. Worked Examples

### 4.1 List the catalogue

```bash
curl http://localhost:8000/api/books/
```

### 4.2 Search

```bash
curl "http://localhost:8000/api/books/?search=django"
```

### 4.3 Filter by author

```bash
curl "http://localhost:8000/api/books/?author=Fitzgerald"
```

### 4.4 Filter by price range, ordered by price descending

```bash
curl "http://localhost:8000/api/books/?min_price=10&max_price=50&ordering=-price"
```

### 4.5 Obtain a JWT and create a book

```bash
# Step 1 — obtain the access token.
ACCESS=$(curl -s -X POST http://localhost:8000/api/auth/token/ \
  -H "Content-Type: application/json" \
  -d '{"username": "admin", "password": "your-password"}' \
  | jq -r .access)

# Step 2 — create a book.
curl -X POST http://localhost:8000/api/books/ \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $ACCESS" \
  -d '{
    "title": "New Book",
    "author": "Author Name",
    "price": "29.99",
    "description": "Description here"
  }'
```

### 4.6 Patch one field

```bash
curl -X PATCH http://localhost:8000/api/books/1/ \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $ACCESS" \
  -d '{"price": "12.50"}'
```

### 4.7 Delete

```bash
curl -X DELETE http://localhost:8000/api/books/1/ \
  -H "Authorization: Bearer $ACCESS"
```

## 5. Status Codes the API Returns

| Code | When |
|------|------|
| `200 OK` | A successful `GET`, `PUT`, `PATCH`, or token verify. |
| `201 Created` | A successful `POST` to `/api/books/`. |
| `204 No Content` | A successful `DELETE`. |
| `400 Bad Request` | The payload failed serializer validation. |
| `401 Unauthorized` | A protected endpoint hit without credentials, or with an expired or malformed JWT. |
| `403 Forbidden` | Authentication present but the caller is not an admin (write verbs). Also returned on CSRF failure for session-authenticated calls. |
| `404 Not Found` | The book ID does not exist — *or* the order ID belongs to another customer (the 404 hides the existence of the resource). |
| `429 Too Many Requests` | The JWT token endpoint's `5/min` anonymous throttle has fired. |

## 6. CSRF Notes

The two authentication modes carry different CSRF expectations:

- **Session-authenticated calls** are protected by `CsrfViewMiddleware`. A browser-based caller that sends the session cookie without the CSRF token receives `403 Forbidden`. This is the case CSRF was designed for and the protection is on by default.
- **JWT-authenticated calls** are not CSRF-protected. They cannot be — there is no cookie for an attacker to ride. The server-side request is a deliberate act by a backend caller holding a bearer token; no cross-origin page is in the loop.

The corollary, useful to know: if a caller wants the convenience of session authentication on the API (because they are already signed in via the website), they must include the CSRF token. If they want stateless cross-origin access, JWT is the right door.

## 7. Where the API Lives in the Codebase

- `catalogue/api.py` — `BookViewSet`, the queryset filters, the `IsAdminUser` permission split.
- `catalogue/serializers.py` — `BookSerializer`, including the read-only `cover_image` field.
- `catalogue/urls.py` — the DRF router that mounts the view set under `/api/books/`.
- `accounts/views.py:230-248` — `JWTLoginThrottle` and `ThrottledTokenObtainPairView` — the throttle that closes the JWT brute-force bypass.
- `config/urls.py` — wires `/api/auth/token/`, `/api/auth/token/refresh/`, `/api/auth/token/verify/`, `/api/docs/`, `/api/redoc/`, `/api/schema/` into the project.
- `config/settings.py` (`REST_FRAMEWORK`, `SPECTACULAR_SETTINGS`, `SIMPLE_JWT`) — pagination, throttle scopes, schema metadata, token lifetimes.
